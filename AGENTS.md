# AGENTS.md

Guidelines for AI coding agents working in the PageZERO docs site (`docs.pagezero.dev`).

Astro + Starlight documentation for the PageZERO starter, deployed as static assets on Cloudflare Workers.

**Stack**: Astro 6, Starlight, TypeScript, Oxlint, Oxfmt, Playwright, Wrangler
**Site**: https://docs.pagezero.dev

## Layout

```
├── src/
│   ├── content/docs/          # Pages — filename is the URL slug
│   │   ├── index.mdx          # Docs home
│   │   ├── getting-started/   # Quick start, tech stack, deployment
│   │   ├── features/          # Product features
│   │   └── components/        # UI component docs
│   ├── assets/                # Images referenced from MDX
│   ├── styles/                # fonts.css, custom.css (theme tokens)
│   └── content.config.ts      # Starlight docs collection
├── e2e/                       # Playwright (`validate.spec.ts`)
├── public/                    # Favicons and other static files
├── astro.config.mjs           # Site, sidebar, markdown, Starlight
└── wrangler.jsonc             # Cloudflare assets deploy from ./dist
```

Sidebar sections in `astro.config.mjs` autogenerate from those three directories. Adding a file is enough; only edit the sidebar config for a new top-level section.

## Hard rules

- Document the starter (`pagezero` repo). Do not invent APIs, flags, or features that are not in that codebase.
- Code samples must match starter conventions: `@/` imports, `createServerFn` in `rpc/` (never in route files), `*.server.ts` is server-only, mutations via `@/form`.
- Pages live in `src/content/docs/`. Use `.mdx` when importing Starlight components; `.md` is fine for prose-only pages.
- Prefer Starlight components (`Steps`, `Aside`, `FileTree`, `Badge`, `LinkButton`, `Tabs`) over custom Astro pages.
- Images go in `src/assets/` and are referenced with relative paths. Favicons go in `public/`.
- Do not turn this into a custom Astro app. Stay on Starlight content collections.
- Positioning and marketing claims should stay consistent with the website `business-strategy` skill. Do not oversell.

## How we do work

### Content

Frontmatter is required. `sidebar.order` controls order inside an autogenerated section:

```mdx
---
title: Quick Start
description: Get up and running with PageZERO in minutes
sidebar:
  order: 1
---
```

Import Starlight components after the frontmatter:

```mdx
import { Steps, Aside, FileTree } from "@astrojs/starlight/components"
```

Mermaid diagrams work in Markdown (`rehype-mermaid`). Shiki highlights other languages.

Component docs typically include a screenshot from `src/assets/`, a Storybook `LinkButton`, then Import / Usage samples copied from the starter.

### Styles

Theme tokens and Starlight overrides live in `src/styles/custom.css`. Fonts in `src/styles/fonts.css`. Wired via `customCss` in `astro.config.mjs`.

### Tests

Playwright: `e2e/validate.spec.ts` against local `http://localhost:3000`. Config: `playwright.config.ts` (`e2e` project; `smoke` when `TEST_PAGE_URL` is set).

## Scripts

```bash
bun run check        # astro check, oxlint, oxfmt --check
bun run check:fix    # oxlint --fix + oxfmt
bun run dev          # Astro dev server (port 3000)
bun run build        # production build → ./dist
bun run preview      # preview the build
bun run start        # wrangler dev --port 3000
bun run test:e2e     # local Playwright
bun run test:smoke   # deployed Playwright
```

CI is `.github/workflows/deploy.yml` (check → e2e → deploy). `main` is production; PRs are preview (`wrangler versions upload`).

## Environment

Node.js >= 24, Bun >= 1.3. No `.env` for local docs.
