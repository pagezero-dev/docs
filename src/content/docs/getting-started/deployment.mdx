PageZERO is built specifically for Cloudflare's infrastructure, leveraging Cloudflare Workers for compute and Cloudflare D1 for database storage.

The deployment process involves setting up D1 databases and deploying your application as Cloudflare Workers.
You can deploy manually or set up automated deployments through a GitHub Actions CI/CD pipeline.

Worker name, D1, and text vars live in `packages/config/cloudflare/`. App values (core, email, payments) stay in `packages/config/`. Select a mode with `--mode` (`production`, `preview`, `development`, `e2e`).

## First deployment

<Steps>

1. **Create a Cloudflare account** - sign up at [dash.cloudflare.com](https://dash.cloudflare.com/sign-up/) if you don't have one yet.

1. **Login to Cloudflare** - in your project root directory, authenticate via the `cf` CLI:

   ```sh
   bunx cf auth login
   ```

1. **Set Worker name and text vars** - edit `packages/config/cloudflare/production.ts` and `packages/config/cloudflare/preview.ts`. Set `workerName` and, when you have them, `CLOUDFLARE_TURNSTILE_PUBLIC_KEY` and `NEWSLETTER_SEGMENT_ID` on `vars` (preview spreads production and can override).

1. **Create D1 databases** - create production and preview databases, then put each returned UUID on the matching `d1[].id` in those files:

   ```sh
   bunx cf d1 create --name <project-name>-production
   ```

   ```sh
   bunx cf d1 create --name <project-name>-preview
   ```

   Use the `d1[].name` values from the config files (typically `<workerName>-production` and `<workerName>-preview`).

   <Aside type="note">
     `cf deploy` can provision D1 databases when `id` is omitted (`--provision` defaults to true).
     It does not write UUIDs back to `packages/config/cloudflare`, and `bun run db:migrate` needs
     those IDs. Create the databases and add them here. See [Develop, build, and
     deploy](https://developers.cloudflare.com/cf/projects/).
   </Aside>

1. **Deploy your app** - Vite-build, then deploy for _production_ and _preview_:

   ```sh
   bun run build --mode production
   bun run deploy --mode production
   ```

   ```sh
   bun run build --mode preview
   bun run deploy --mode preview
   ```

1. **Migrate your database** - apply migrations to the remote preview and production databases:

   ```sh
   bun run db:migrate --mode preview
   ```

   ```sh
   bun run db:migrate --mode production
   ```

1. **Your app is now ready! 🎉** - with its core functionality.

   To enable additional features such as authentication, email delivery, and payments, follow the setup sections in the [Authentication](/features/authentication#setup), [E-mail](/features/email#setup), and [Payments](/features/payments#setup) documentation.

</Steps>

## Automatic deployment

Automatic deployment happens through the GitHub Actions CI/CD pipeline. Once the pipeline is set up,
every merge to the `main` branch will automatically trigger deployment to Cloudflare Workers and a database
migration for Cloudflare D1. Additionally, every PR will trigger a preview deployment, allowing you to access a
specific version of your app for each PR.

<Aside type="note" title="Prerequisites">
  Steps below require [GitHub CLI](https://cli.github.com/).
</Aside>

<Steps>
1. **Complete the first deployment** - follow the [First deployment](#first-deployment) steps above to deploy your app and run database migrations.

1.  **Login to GitHub** - authenticate via the `gh` CLI:

    ```sh
    gh auth login
    ```

1.  **Create a GitHub repository** - create a private repo and push all changes:

    ```sh
    gh repo create <project-name> --private --source=. --remote=origin --push
    ```

    <Aside type="note">Skip this step if your project is already hosted on GitHub.</Aside>

1.  **Add repository variable** - set your Cloudflare account ID:

    ```sh
    gh variable set CLOUDFLARE_ACCOUNT_ID --body "<your-cloudflare-account-id>"
    ```

    <Aside type="note">
      `CLOUDFLARE_ACCOUNT_ID` value can be obtained through `bunx cf auth whoami`.
    </Aside>

1.  **Add repository secret** - set your Cloudflare API token:

    ```sh
    gh secret set CLOUDFLARE_API_TOKEN
    ```

    ```sh
    gh secret set CLOUDFLARE_API_TOKEN --app dependabot
    ```

    <Aside type="note">
      `CLOUDFLARE_API_TOKEN` value can be obtained through the Cloudflare dashboard under "Manage
      account / Account API Tokens". You will need to create a new token there. The token will
      require the following permissions: `D1:Edit`, `Workers Scripts:Edit`. The secret for
      Dependabot needs to be set separately; otherwise, Dependabot PRs will not perform preview
      deployments. CI authenticates with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
    </Aside>

1.  **Done! 🎉**

    Now let's test the pipeline. Create a PR in your GitHub repository. An action will be triggered in the "Actions" section. If the basic checks pass, the workflow will perform a preview deployment to Cloudflare Workers and run a database migration on your preview database. After deployment, a "View deployment" button will appear in your PR with a link to the preview.

    When you merge the PR to `main`, a production deployment will occur and a database migration will be performed on your production database.

</Steps>
